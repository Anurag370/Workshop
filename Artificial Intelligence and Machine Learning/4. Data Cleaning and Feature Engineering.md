# 10. Types of Missing Data

Statistically, missingness is often discussed as:

### MCAR — Missing Completely At Random

Missingness is unrelated to observed or unobserved variables.

### MAR — Missing At Random

Missingness depends on other observed variables.

### MNAR — Missing Not At Random

Missingness depends on the missing value itself or an unobserved factor.

These distinctions matter when choosing an imputation strategy.

# 12. Removing Missing Values

Remove rows:

```python

```

Remove rows where a particular column is missing:

```python

    subset=["Age"]
)
```

Remove columns:


> [!warning]  
> Removing too many rows can cause significant information loss and may introduce bias if missingness is not random.

# 13. Mean Imputation

Replace missing numerical values with the mean.

```python
df["Age"] = df["Age"].fillna(
    df["Age"].mean()
)
```

Example:

```text
20
22
NaN
24
```

Mean:

20+22+243=22\frac{20+22+24}{3}=22

Missing value becomes:

```text
22
```

### When useful?

Works reasonably when:

- Data is approximately symmetric
    
- Outliers are limited
    

---

# 14. Median Imputation

Replace missing values with the median.

```python
df["Salary"] = df["Salary"].fillna(
    df["Salary"].median()
)
```

Median is often preferred when the data contains outliers or is strongly skewed.

Example:

```text
20
22
23
25
500
```

Mean is heavily affected by `500`.

Median is more robust.

# 19. Important Rule — Avoid Data Leakage During Imputation

> [!danger]  
> **Never calculate imputation statistics using the test set.**

Incorrect:

```text
Entire Dataset
     ↓
Calculate Mean
     ↓
Fill Missing Values
     ↓
Train/Test Split
```

The test set influenced preprocessing.

Correct:

```text
Dataset
   ↓
Train/Test Split
   │
   ├── Training Data
   │       ↓
   │    Calculate Mean
   │       ↓
   │    Transform Train
   │
   └── Test Data
           ↓
     Use Training Mean
           ↓
      Transform Test
```

Scikit-learn pipelines are useful for enforcing this workflow.

# 29. IQR Method

The Interquartile Range is:

IQR=Q3−Q1IQR = Q_3-Q_1

Where:

- $Q_1$ = 25th percentile
    
- $Q_3$ = 75th percentile
    

Lower bound:

Q1−1.5(IQR)Q_1 - 1.5(IQR)

Upper bound:

Q3+1.5(IQR)Q_3 + 1.5(IQR)

Values outside these bounds are commonly flagged as potential outliers.

---

# 30. Detecting Outliers with Python

```python
Q1 = df["Salary"].quantile(0.25)
Q3 = df["Salary"].quantile(0.75)

IQR = Q3 - Q1

lower = Q1 - 1.5 * IQR
upper = Q3 + 1.5 * IQR

outliers = df[
    (df["Salary"] < lower) |
    (df["Salary"] > upper)
]
```

---

# 31. Z-Score

The Z-score measures how many standard deviations a value is away from the mean.

z=x−μσz = \frac{x-\mu}{\sigma}

Where:

- $x$ = observation
    
- $\mu$ = mean
    
- $\sigma$ = standard deviation
    

A common heuristic is to flag observations with:

∣z∣>3|z| > 3

as potential outliers.

# 43. TF-IDF

**TF-IDF** stands for:

> Term Frequency — Inverse Document Frequency

It measures how important a word is to a document relative to a collection of documents.

Conceptually:

TF-IDF=TF×IDFTF\text{-}IDF = TF \times IDF

Common words across many documents tend to receive lower importance, while words more specific to particular documents can receive higher weights.

Scikit-learn:

```python
from sklearn.feature_extraction.text import TfidfVectorizer

vectorizer = TfidfVectorizer()

X = vectorizer.fit_transform(
    df["text"]
)
```

# 46. Label Encoding

Label encoding assigns integers to categories.

Example:

```text

Dog → 1
Horse → 2
```

However, for nominal categories this can accidentally imply:

```text
Horse > Dog > Cat
```

which may not have any real meaning.

Therefore, label encoding is generally more appropriate for **target labels** or situations where the encoding matches an actual ordered relationship.

# 62. Data Leakage

> [!danger]  
> **Data leakage occurs when information unavailable at prediction time is accidentally used during training.**

Example:

Suppose you want to predict whether a student will pass.

Features:

```text
Study Hours
Attendance
Assignment Scores
Final Exam Score
```

Using:

```text
Final Exam Score
```

to predict whether the student passes may leak information because the final exam score may only be known **after** the outcome is determined.

---

# 63. Types of Leakage

### Target Leakage

A feature directly or indirectly contains information about the target.

### Train-Test Contamination

Information from the test set influences training or preprocessing.

Example:

```text
Entire Dataset
     ↓
Scaling
     ↓
Train/Test Split
```

Incorrect.

Correct:

```text
Train/Test Split
      ↓
Fit scaler on training data
      ↓
Transform training data
      ↓
Transform test data using same scaler
```

# 64. Scikit-Learn Pipeline

Pipelines help organize preprocessing and modeling.

Example:

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])

pipeline.fit(X_train, y_train)

predictions = pipeline.predict(X_test)
```

This ensures that preprocessing is fitted as part of the training process.

# 65. ColumnTransformer

Different columns often need different preprocessing.

Example:

```text

```

Use `ColumnTransformer`:

```python
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import (
    StandardScaler,
    OneHotEncoder
)

preprocessor = ColumnTransformer([
    (
        "num",
        StandardScaler(),
        ["Age", "Salary"]
    ),
    (
        "cat",
        OneHotEncoder(
            handle_unknown="ignore"
        ),
        ["City", "Gender"]
    )
])
```

# 70. Good Feature Engineering Principles

### 1. Understand the domain

Feature engineering should be guided by domain knowledge.

### 2. Avoid leakage

Never use information that would not be available at prediction time.

### 3. Keep transformations reproducible

Use pipelines where possible.

### 4. Validate engineered features

Check:

- Missing values
    
- Distribution
    
- Range
    
- Meaning
    
- Correlation
    
- Potential leakage
    

### 5. Don't create features blindly

More features do not automatically mean a better model.

# 71. Curse of Dimensionality

Adding too many features can create problems.

As the number of dimensions increases:

- Data becomes sparse
    
- Distance measures can become less informative
    
- Computational cost increases
    
- Overfitting risk can increase
    

This phenomenon is called the **curse of dimensionality**.

Therefore:

```text
More Features
     ≠
Better Model
```

The goal is:

```text
Useful Features
     ↓
Better Representation
     ↓
Better Generalization
```

# 81. Final Summary

Data preparation is one of the most important stages of Machine Learning.

The complete idea is:

```text
Raw Data
   ↓
Inspect
   ↓
Clean
   ├── Missing Values
   ├── Duplicates
   ├── Invalid Values
   ├── Data Types
   └── Outliers
   ↓
Transform
   ├── Encoding
   ├── Scaling
   └── Normalization
   ↓
Feature Engineering
   ├── New Features
   ├── Date Features
   ├── Ratios
   ├── Interactions
   └── Text Features
   ↓
Feature Selection
   ↓
Train ML Model
   ↓
Evaluate
```

### The core principle:

> **Garbage In → Garbage Out**

A sophisticated Machine Learning algorithm cannot reliably compensate for fundamentally poor data.

The goal of data preparation is therefore not simply to make a dataset "clean." It is to create a **valid, informative, leakage-free representation of the problem** that allows the ML algorithm to learn meaningful patterns.
